# Keitaro campaign tool

Сервис на FastAPI + SQLAlchemy для работы с рекламным трекером Keitaro через Admin API v1:

1. **Создание кампании** по названию, гео и ID оффера. Создаётся кампания и два потока:
   - поток 1: трафик из указанных стран → редирект на `https://google.com`;
   - поток 2: весь остальной трафик → выбранный оффер (доля 100%).

   У кампании настроены домен, группа и источник. Если группы или источника `FORTESTS` нет, они создаются.
2. **Редактор существующей кампании**: добавление и удаление офферов в потоке с пересчётом долей, ручная правка долей, история правок.

## Быстрый старт

Нужен Python 3.11–3.13.

```bash
python3.12 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env          # впишите KEITARO_URL и KEITARO_API_KEY
alembic upgrade head          # миграции БД
uvicorn app.main:app --reload
```

Откройте http://127.0.0.1:8000. Документация API: http://127.0.0.1:8000/docs.

### Демо без доступа к трекеру

```bash
KEITARO_FAKE=1 uvicorn app.main:app --reload
```

Вместо Keitaro работает эмулятор в памяти (`app/keitaro/fake.py`) с тестовыми доменами и офферами. После перезапуска его данные пропадают.

## Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `KEITARO_URL` | — | адрес трекера, с `/admin_api/v1` или без |
| `KEITARO_API_KEY` | — | ключ из «Профиль → API ключи» |
| `KEITARO_FAKE` | `0` | `1` — работать с эмулятором |
| `DATABASE_URL` | `sqlite:///./app.db` | любая БД SQLAlchemy, например `postgresql+psycopg://...` (драйвер ставится отдельно) |
| `DEFAULT_DOMAIN` | — | домен новых кампаний; если не найден, берётся первый |
| `DEFAULT_GROUP_NAME` | `FORTESTS` | группа новых кампаний |
| `DEFAULT_SOURCE_NAME` | `FORTESTS` | источник трафика новых кампаний |
| `SAFE_REDIRECT_URL` | `https://google.com` | куда уходит трафик из указанных стран |

В форме создания домен, группу и источник можно выбрать вручную (блок «Домен, группа, источник»).

## Миграции

```bash
alembic upgrade head      # применить
alembic downgrade -1      # откатить последнюю
alembic revision --autogenerate -m "описание"   # новая миграция после правки app/models.py
```

URL базы Alembic берёт из `DATABASE_URL`.

## Как устроено

```
app/
  keitaro/client.py   клиент Admin API (httpx, заголовок Api-Key)
  keitaro/fake.py     эмулятор Keitaro с тем же интерфейсом
  services/campaigns.py  создание кампании и потоков, откат при ошибке
  services/editor.py     добавление/удаление офферов, ручные доли, история
  services/shares.py     расчёт долей
  models.py           SQLAlchemy: created_campaigns, offer_changes
  api.py, main.py     FastAPI
  static/             фронтенд: HTML + чистый JS
migrations/           Alembic
```

**Keitaro — источник правды.** Кампании, потоки и офферы читаются из трекера при каждом запросе, поэтому редактор работает и с кампаниями, созданными не через этот сервис. В своей БД хранится только:
- `created_campaigns` — что и с какими параметрами создано через сервис;
- `offer_changes` — журнал правок офферов: что было и что стало.

### Создание кампании

1. Проверка: название не пустое, гео — двухбуквенные коды ISO (`mx, AU;ro` → `MX, AU, RO`), оффер есть в Keitaro.
2. `POST /campaigns`: тип `position` (ротация потоков по позиции), домен, группа, источник, случайный alias.
3. `POST /streams` дважды:
   - позиция 1, схема `redirect` на safe-URL, фильтр `country accept [...]`;
   - позиция 2, схема `landings` с оффером, доля 100.
4. Если поток не создался, кампания удаляется, чтобы в трекере не оставалась пустая кампания.

### Доли офферов

Доли — целые проценты, сумма всегда ровно 100.

- **Поровну** (по умолчанию): 1 оффер — 100, 2 — 50/50, 3 — 34/33/33. Остаток раздаётся первым офферам по одному проценту.
- **Сохранять пропорции**: новый оффер получает 100/n, остальные делят оставшееся в прежней пропорции. При удалении оставшиеся масштабируются до 100. Округление методом наибольшего остатка.
- **Вручную**: на странице редактора можно задать доли, сервер проверяет, что сумма равна 100.

Ограничения: оффер нельзя добавить в поток дважды; последний оффер удалить нельзя, иначе поток останется пустым; в потоке-редиректе офферов нет, его редактор не трогает.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/meta` | домены, группы, источники, значения по умолчанию |
| GET | `/api/offers?q=` | поиск офферов по названию или ID (автокомплит) |
| POST | `/api/campaigns` | создать кампанию `{name, geo, offer_id, domain_id?, group_id?, source_id?}` |
| GET | `/api/campaigns` | список кампаний из Keitaro |
| GET | `/api/campaigns/{id}` | кампания с потоками и офферами |
| GET | `/api/campaigns/{id}/history` | история правок офферов |
| POST | `/api/streams/{id}/offers` | добавить оффер `{offer_id, mode}` |
| DELETE | `/api/streams/{id}/offers/{offer_id}?mode=` | удалить оффер |
| PUT | `/api/streams/{id}/offers` | задать доли вручную `{offers: [{offer_id, share}]}` |

Ошибки: 400 — неверные данные, 404 — не найдено, 4xx от Keitaro возвращаются как есть, недоступность трекера — 502.

```bash
python scripts/smoke.py http://127.0.0.1:8000
```

## Допущения

- Видео с примером редактора без звука и описания, поэтому логика долей восстановлена по ТЗ и скриншотам: при добавлении и удалении доли пересчитываются поровну, есть режим с сохранением пропорций и ручная правка.
- Поля запросов (`schema`, `action_type`, `filters`, `offers`) взяты из документации Admin API v1 и проверены на эмуляторе. Перед первым запуском на боевом трекере стоит прогнать `scripts/smoke.py` на тестовой группе `FORTESTS`.
- Авторизация в самом сервисе не сделана: предполагается запуск во внутренней сети.
